## 1. 产品概述

### 1.1 背景

情侣、朋友结伴出游时，拍照的人往往不是专业摄影师，而是男朋友、闺蜜或旅伴。结果是：

- **拍不出**：构图糟糕（人太小、顶天立地、背景杂乱、地平线歪斜）
- **摆不好**：被拍的人尴尬僵硬，只会比耶，不知道怎么站、手放哪、看哪里
- **调不对**：不知道站多远、用几倍变焦、机位该多高、该顺光还是逆光
- **选不出**：一次拍几十张，挑不出一张能发朋友圈的

现有产品要么是「修图工具」（事后补救），要么是「姿势图库」（需要用户自己找、自己套），**没有一个产品在拍摄当下同时指导摄影师和被拍者**。

### 1.2 产品定位

**一句话**：打开相机，实时告诉「拍照的人」怎么拍、告诉「被拍的人」怎么摆的 AI 旅拍教练。

- 产品形态：以相机为主界面的拍摄辅助 App
- 核心差异：**实时闭环**——不是给建议，而是告诉用户「还差多少、往哪调、到位了没有」
- 不做的事：不做修图软件、不做社交社区、不做相机替代品

### 1.3 目标用户

| 维度 | 描述 |
|---|---|
| 核心人群 | 20–35 岁情侣、闺蜜、朋友结伴出游 |
| 摄影师画像 | 非专业、不想学摄影、怕被骂、希望「照着做就行」 |
| 被拍者画像 | 想要好看的照片、但不会摆姿势、面对镜头容易僵 |
| 使用场景 | 景区地标、海边日落、城市街拍、咖啡馆、花海、夜景 |
| 设备特征 | 中高端 Android 手机（骁龙 7 系 / 天玑 8000 及以上） |

### 1.4 核心价值主张

1. **对摄影师**：把「我不知道怎么拍」变成「照着清单调就行」，降低学习成本和心理压力
2. **对被拍者**：把「我不知道怎么摆」变成「照着剪影站就行」，降低尴尬感
3. **对关系**：减少「你怎么又拍成这样」的沟通摩擦，这是最强的传播点

### 1.5 非目标（明确不做）

- 不做专业摄影教学（不服务摄影爱好者进阶需求）
- 不做修图/滤镜商城（V2 之后再评估）
- 不做社交社区、作品广场
- 不做云端相册、跨设备同步
- 不做视频拍摄指导（仅静态照片）
- 不做前置摄像头自拍模式（V2 评估）

## 2. 使用场景与核心流程

### 2.1 典型场景

**场景 A：景区地标打卡**
摄影师举着手机，人站在地标前 3–5 米。App 识别地标类场景，建议「人物放右侧三分线、地标留左上、机位略低仰拍」，并给出全身站姿。

**场景 B：海边日落**
逆光环境。App 识别逆光，建议「侧身 45°、降低机位、人物占画面 50%、曝光补偿 +0.7」，并提示「别让太阳直射镜头」。

**场景 C：城市街拍**
背景杂乱、有路人。App 检测杂物与人流，提示「向左移半步，用墙面做背景」，并建议走动抓拍姿势。

**场景 D：咖啡馆室内**
光线偏暗、空间狭窄。App 建议「坐姿、靠窗侧光、半身构图、机位与视线平齐」，并给出坐姿模板。

### 2.2 核心用户流程

```
打开 App
  → 权限引导 / 机型检测（仅首次）
  → 后置相机预览
  → 自动识别场景 + 光线 + 人物
  → 生成「本次拍摄方案」：构图 + 姿势 + 机位参数
  → 屏幕出现：构图辅助线 + 姿势剪影 + 待办清单
  → 摄影师按清单调整（语音 + 视觉双重提示）
  → 每项到位自动打勾，全部到位后提示「可以拍了」
  → 一键应用参数（或手动）→ 倒计时 → 连拍
  → 立即评分 → 推荐最佳一张 → 保存 / 重拍
  → 会话结束：本次成片 N 张，最佳 Top 3
```

### 2.3 关键用户故事

| 编号 | 用户故事 | 验收要点 |
|---|---|---|
| US-01 | 作为摄影师，我打开相机就能看到该怎么构图 | 2 秒内出现构图建议 |
| US-02 | 作为摄影师，我知道要后退多少、手机举多高 | 待办清单实时更新完成状态 |
| US-03 | 作为被拍者，我能看到自己要摆成什么样 | 剪影叠加在取景框内，可对齐 |
| US-04 | 作为摄影师，我不想一直盯着屏幕 | 关键指令有语音播报 |
| US-05 | 作为用户，我希望 App 自动帮我调好变焦和曝光 | 一键应用，可撤销 |
| US-06 | 作为用户，我拍完想知道哪张最好 | 10 秒内给出评分和 Top 3 |
| US-07 | 作为用户，我在景区没信号也能用 | 断网全功能可用 |

## 3. 功能需求

优先级说明：**P0 = MVP 必须**，**P1 = 第二版**，**P2 = 远期规划**。

### 3.1 相机与实时分析（P0）

| 需求 | 说明 |
|---|---|
| 后置相机预览 | CameraX，全屏预览，支持 16:9 / 4:3 切换 |
| 实时帧分析 | `ImageAnalysis` 输出 640×480 YUV，仅保留最新帧（`STRATEGY_KEEP_ONLY_LATEST`） |
| 场景识别 | 识别 8 大类：海边 / 山地 / 城市街道 / 古镇建筑 / 室内 / 花海草地 / 夜景 / 雪景 |
| 光线识别 | 顺光 / 侧光 / 逆光 / 弱光 / 强光溢出 |
| 人物检测 | 人物数量、是否完整入镜、人体框、朝向 |
| 背景元素 | 地平线水平度、天空/水面/地面分割、显著杂物、路人 |
| IMU 数据 | 通过重力/陀螺仪计算手机俯仰角与水平度（精度 ±0.5°，不依赖视觉） |

**验收标准**
- 场景识别准确率 ≥ 80%（8 类，自建测试集 500 张）
- 人物检测召回率 ≥ 95%（单人、距离 1–8 米）
- 地平线角度误差 ≤ 1°
- 手机俯仰角误差 ≤ 0.5°

### 3.2 构图指导（P0）

**识别项**
- 主体占比（人物框高度 / 画面高度）
- 头顶留白比例
- 主体在九宫格中的位置
- 地平线水平度与位置
- 背景杂物干扰度
- 关节切割（是否切头、切脚、切腰）

**建议规则（按景别）**

| 景别 | 人物占画面高度 | 头顶留白 | 适用 |
|---|---|---|---|
| 环境人像 / 全身 | 40%–65% | 3%–8% | 地标、海边、街道 |
| 半身 | 60%–85% | 3%–8% | 咖啡馆、室内、近景 |
| 特写 / 头肩 | 70%–90% | 2%–6% | 情绪人像、夜景 |

**呈现方式**
- 九宫格辅助线（可开关）
- 主体建议框（虚线），人物框进入后变绿
- 地平线水平仪（倾斜时变红）
- 一句话人话提示，例：「把人物放到右边这条线上，塔放在左边」

**验收标准**
- 构图项判定与人工标注一致率 ≥ 85%
- 提示文案单条 ≤ 20 字
- 提示刷新频率 ≤ 2 次/秒，避免闪烁

### 3.3 姿势推荐（P0）

**输入**：场景类型、光线、景别、人物朝向、人物框位置、服装主色（可选）

**输出**：2–3 个推荐姿势，每个包含
- 真人示例图（1:1 或 3:4）
- 骨架剪影（可叠加到取景框，半透明）
- 1–3 句摄影师引导话术
- 难度等级（简单 / 中等 / 需要互动）

**姿势库（MVP：60–80 个）**

| 分类 | 数量 | 示例 |
|---|---|---|
| 站姿 | 25 | 侧身回眸、手插口袋、手扶帽檐、单脚点地 |
| 坐姿 | 15 | 台阶坐、抱膝、侧坐回望、托腮 |
| 走动 / 动态 | 10 | 向前走抓拍、裙摆转身、跳跃 |
| 互动 / 道具 | 10 | 举相机、拿咖啡、撑伞、抱花 |
| 双人（P1） | 20 | 牵手走、背靠背、对视、搂肩 |

**剪影叠加**
- 剪影按人物框自动缩放、对齐
- 关键点对齐度实时计算，输出 0–100% 匹配度
- 匹配度 ≥ 75% 判定为「到位」

**验收标准**
- 姿势推荐与场景匹配度人工评分 ≥ 4/5（内测 30 人）
- 剪影对齐度计算延迟 ≤ 50ms
- 单场景推荐姿势数 2–3 个，不刷屏

### 3.4 机位与参数指导（P0）★核心

输出一份**待办清单**，最多同时显示 3 项，完成一项补一项。

**可检测项**

| 项目 | 检测方式 | 精度 |
|---|---|---|
| 后退 / 前进距离 | 单目测距（针孔模型 + 人体框高度） | ±15%，只给 0.5 米粒度 |
| 机位高度（平视/略低/略高） | IMU 俯仰角 + 人物框中心位置 | ±0.5° |
| 手机水平度 | IMU 横滚角 | ±0.5° |
| 变焦倍数 | CameraX ZoomState 读取 | 精确 |
| 主体位置 | 视觉人体框中心 | ±3% 画面 |
| 背景杂物避让 | 分割 + 显著物体检测 | 定性 |
| 顺光/逆光 | 人脸区域亮度 vs 背景亮度 | 定性 |

**测距公式**

```
d ≈ (f_px × H_real) / h_px

f_px : 焦距（像素）= 焦距(mm) × 画面宽度(px) / 传感器宽度(mm)
H_real : 人物真实身高（默认 165cm，可由用户设置）
h_px : 画面中人体框像素高度
```

**引导策略（关键设计）**
- **绝对距离只做参考**，文案用「约」：「再后退约 1 米」
- **主引导用相对描述**：「再远一点，让人物占画面一半高」
- 双校验：距离估算 + 画面占比同时满足才判定到位
- 抖动抑制：连续 3 帧满足阈值才打勾，避免来回跳

**验收标准**
- 测距误差 ≤ 20%（1–8 米范围）
- 待办项到位判定准确率 ≥ 90%
- 同一提示重复间隔 ≥ 3 秒

### 3.5 相机参数一键应用（P0）

**可自动控制**

| 能力 | 实现 |
|---|---|
| 变焦 | `CameraControl.setZoomRatio()`，范围从 `ZoomState` 读取 |
| 曝光补偿 | `setExposureCompensationIndex()` |
| 对焦 | `startFocusAndMetering()`，对焦到人脸框 |
| 闪光灯 | `enableTorch()`（仅弱光建议开启） |
| 网格 / 水平仪 | App 自绘 |

**不可自动控制（只能引导）**
- 物理距离、机身角度、人物姿势、背景选择

**三档模式**

| 模式 | 行为 | 默认 |
|---|---|---|
| 仅建议 | 只提示，不动相机 | — |
| 一键应用 | 用户点「应用」后生效，可撤销 | ✅ 默认 |
| 全自动 | 参数变化时自动应用 | P1，设置内开启 |

**约束**
- 每次自动变更必须有轻提示（Toast / 音效）
- 变更后 3 秒内可「撤销」
- 变焦 > 3x 时提示「数码变焦，画质会下降」

**验收标准**
- 参数应用成功率 ≥ 98%（目标机型白名单内）
- 应用后预览无明显卡顿（≤ 200ms 黑屏）

### 3.6 拍摄执行（P0）

| 功能 | 说明 |
|---|---|
| 快门 | 大按钮 + 音量键 |
| 倒计时 | 3s / 5s / 10s，语音报数「3、2、1，笑」 |
| 连拍 | 3 / 5 / 10 张，间隔 300ms |
| 定时 | 用于三脚架模式（P1） |
| 拍摄反馈 | 快门音 + 震动 + 短暂缩略图 |

### 3.7 语音与反馈（P0）

**语音策略**
- 固定指令用**预录音频**（约 80 条），零延迟、音质稳定
- 动态数字（距离、倍数）用 TTS 拼接，失败则降级为纯视觉 + 震动
- 支持男声 / 女声，可关闭

**播报规则**
- 优先级：关键调整 > 构图 > 鼓励语
- 单条 ≤ 12 字
- 全局最小间隔 1.5 秒，同一指令冷却 3 秒
- 队列长度上限 3，超出丢弃低优先级
- 到位的正向反馈：「好，就这样」

**其他反馈**
- 到位：短震动 + 上扬音效
- 未到位：无惩罚性反馈（不播报「错了」）
- 静音场景（检测到室内/博物馆标签）：自动切震动模式

**验收标准**
- 语音播报延迟 ≤ 300ms
- 连续使用 10 分钟，用户主观「不烦」评分 ≥ 4/5

### 3.8 拍后评分与选片（P0）

**单张评分（0–100）**

| 维度 | 权重 | 方法 |
|---|---|---|
| 清晰度 | 30% | 拉普拉斯方差，人脸区域加权 |
| 曝光 | 20% | 直方图溢出比例 + 人脸亮度 |
| 构图 | 20% | 主体位置 / 占比 / 水平度 |
| 姿态 | 20% | 关键点与目标姿势匹配度、关节遮挡 |
| 表情 | 10% | 闭眼检测（P1 加微笑检测） |

- ≥ 80 分：推荐
- ≥ 90 分：精选
- 检测到闭眼：直接降档并提示

**选片**
- 一组连拍自动排序，推荐 Top 3
- 支持左右滑动对比
- 一键保存 / 删除 / 重拍

**验收标准**
- 评分与人工排序的 Top1 一致率 ≥ 65%
- 单张评分耗时 ≤ 300ms（1080P）

### 3.9 场景模板与姿势库（P0 内容建设）

**首发场景包（8 个）**

| 场景 | 光线 | 主打构图 | 姿势数 |
|---|---|---|---|
| 海边日落 | 逆光/侧逆光 | 剪影、低机位 | 12 |
| 城市街道 | 顺光/侧光 | 引导线、三分法 | 12 |
| 古镇建筑 | 顺光 | 框架构图、对称 | 10 |
| 山地草原 | 顺光 | 低机位、大留白 | 10 |
| 花海草地 | 顺光/侧光 | 半身、前景虚化 | 10 |
| 咖啡馆室内 | 侧窗光 | 半身、平视 | 8 |
| 夜景城市 | 弱光 | 高感、霓虹背景 | 8 |
| 雪景 | 强反光 | 高调、居中 | 6 |

**内容规范**
- 示例图统一 3:4 竖构图、统一调色风格
- 每个姿势必须配 1–3 句可念出口的话术
- 素材版权必须自有或已授权（见风险章节）

### 3.10 设置与机型适配（P0）

- 首次启动：机型性能检测（跑 20 帧基准）→ 分配性能档位
- 档位：A（高）/ B（中）/ C（降级）
- 设置项：语音开关、音色、网格、水平仪、性能模式、清空数据
- 隐私说明：全本地处理，不申请网络权限

### 3.11 P1 / P2 功能

**P1**
- 双人 / 情侣模式（两人位置关系、身高差、互动姿势）
- 路人模式：大字 + 语音指挥陌生人
- 最佳帧自动挑选（连拍中选表情最佳）
- 姿势难度分级与新手引导
- 云端模型热更新（可选，需联网授权）

**P2**
- 三脚架模式 + 模特端第二台设备同步
- AI 生成个性化姿势示意
- 旅拍滤镜 / 调色
- 分享模板、水印
- 多语言

### 4.2 文案原则

1. **说人话**：不说「主体占比不足」，说「人再大一点」
2. **给动作**：不说「构图不好」，说「往左移半步」
3. **只给一条**：同一时刻最多 2 条指令
4. **正向反馈**：到位说「好，就这样」，不说「对了」
5. **不责备**：永远不出现「错了」「不行」

### 4.3 文案示例

| 场景 | 提示 |
|---|---|
| 人太小 | 「再靠近一点，让人占画面一半」 |
| 顶天立地 | 「头顶留一点空，别切到头发」 |
| 地平线歪 | 「手机端平，让海平面水平」 |
| 背景有路人 | 「向左移半步，避开后面的人」 |
| 逆光 | 「侧身站，别让太阳在正后方」 |
| 机位太高 | 「蹲一点，镜头到胸口高度」 |
| 变焦过度 | 「用 2 倍就好，5 倍会糊」 |
| 到位 | 「好，就这样，准备拍」 |

## 5. 技术方案

### 5.1 总体架构

```
┌──────────────────────────────────────────┐
```

### 5.3 模型选型

| 任务 | 方案 | 模型大小 | 目标耗时（Tier B） |
|---|---|---|---|
| 人体姿态 | MediaPipe Pose Landmarker (lite) | ~6MB | 15–25ms |
| 人像分割 | MediaPipe Selfie Segmentation | ~3MB | 20–35ms |
| 场景分类 | MobileNetV3-Small（自训练 8 类） | ~5MB | 5–10ms |
| 人脸 / 闭眼 | MediaPipe Face Detector | ~2MB | 5–10ms |
| 单目深度（P1） | Depth Anything V2 Small / MiDaS Small | 30–60MB | 80–150ms |

- 全部使用 **arm64-v8a**，模型打包进 APK
- 不使用 ARCore / ML Kit 的 GMS 依赖能力
- 可选备选运行时：MNN（阿里）/ ncnn（腾讯），用于后续替换或对比

### 5.4 推理调度策略

| 任务 | 频率 | 说明 |
|---|---|---|
| 姿态 | 每帧 / 每 2 帧 | 核心，必须实时 |
| 分割 | 每 3–5 帧 | 变化慢，可降频 |
| 场景 | 每 1 秒 | 变化极慢 |
| 人脸 | 每 5 帧 | 仅拍前/拍后需要 |
| 深度 | 每 0.5–1 秒 | P1，只在人物 ROI 上跑 |

- 单推理线程 + 最新帧丢弃，避免排队延迟
- ROI 裁剪：仅对人物框外扩 20% 的区域做高成本推理

### 5.5 性能分级与降级

| 档位 | 机型参考 | 预览 | 推理 | 能力 |
|---|---|---|---|---|
| A | 骁龙 865+ / 8 Gen / 天玑 9000+ | 30fps | 15fps | 全功能 |
| B | 骁龙 778G–870 / 天玑 8100–8200 | 30fps | 10fps | 全功能，深度关闭 |
| C | 低于上述 | 30fps | 5–8fps | 仅构图 + 基础姿势，无剪影对齐 |

- 冷启动跑 20 帧基准测试自动定档，允许用户手动覆盖
- 热降级：`PowerManager.getCurrentThermalStatus()`
  - ≥ `THERMAL_STATUS_MODERATE`：推理降到 5fps
  - ≥ `THERMAL_STATUS_SEVERE`：只保留构图提示

### 5.6 隐私与离线

- **不申请 `INTERNET` 权限**（MVP），从系统层面保证照片不出设备
- 相机帧只在内存中处理，不落盘
- 照片通过 MediaStore 保存到系统相册
- 无账号、无埋点上报（或仅本地统计）

### 5.7 机型兼容

- `minSdk 29`（Android 10）、`targetSdk` 跟随最新
- 仅 `arm64-v8a`
- 相机能力探测：变焦范围、曝光补偿范围、是否支持 60fps 预览
- 建立机型白名单 + 灰度名单，异常机型自动降级

### 5.8 目标机型基线（POC 基准机）

**一加 Ace Pro**（2022-08，ColorOS / Android 12+）

| 项目 | 参数 | 对项目的影响 |
|---|---|---|
| SoC | 骁龙 8+ Gen 1（台积电 4nm） | 定为 **Tier A**，姿态 + 分割全开无压力；相比 8 Gen 1 的三星工艺，长时间负载下温控明显更好 |
| CPU | 1×X2 3.2GHz + 3×A710 + 4×A510 | 单线程强，适合「单线程串行推理」调度 |
| GPU | Adreno 730 | 后续可开 TFLite GPU delegate，预计姿态耗时可再降 40%–60% |
| NPU | Hexagon（NNAPI 可用） | 但 NNAPI 在各厂商实现差异大，**POC 阶段先用 CPU 拿基线数据**，再对比 NNAPI |
| 内存 | 12/16GB LPDDR5 | PSS ≤ 400MB 的目标宽松，可放心预载模型 |
| 屏幕 | 6.7" 2412×1080 120Hz | 预览取 640×480 分析与 1080p 预览解耦，避免大分辨率推理 |
| 相机 | 50MP 主摄（IMX766）+ OIS | `CameraControl` 的变焦/曝光/对焦可用；变焦上限需运行时读取 `ZoomState` |
| 续航 | 4800mAh + 150W | 30 分钟耗电 ≤25% 的验收余量充足 |

**POC 阶段需要在这台机器上确认的四件事**

1. `CameraX` 能否拿到 `OUTPUT_IMAGE_FORMAT_RGBA_8888`（决定是否要回退到 YUV 转换）
2. `ZoomState.maxZoomRatio` 的真实值，以及 2x/3x 是否为无损裁切
3. 姿态 + 分割串行推理的实际 fps 与单帧耗时（CPU delegate 基线）
4. 连续 10 分钟机身后盖温度与 `getCurrentThermalStatus()` 的联动曲线

**ColorOS 特有风险**

- 后台进程回收激进：POC 与正式版都不要依赖后台保活，切走即暂停推理
- 省电模式可能限制 CPU 频率：需在 `PerformanceManager` 不可用时给出「性能模式」手动开关
- 相机权限可能有「仅本次允许」选项：每次冷启动都要校验

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 模型精度不达预期 | 提示错误，用户失去信任 | POC 提前验证；阈值保守；宁可不说也不说错 |
| 测距误差大 | 用户按提示走仍不对 | 绝对距离只做参考，主用相对引导 + 画面占比 |
| 发热/耗电 | 无法长时间使用 | 分级调度、热降级、ROI 推理 |
| 机型碎片化 | 部分机型不可用 | 白名单 + 首启基准 + 灰度 |
| 第三方变焦为数码裁切 | 画质下降被吐槽 | 提示话术诚实，优先建议靠近 |
| 语音打扰 | 用户关闭语音 | 节流、可关、静音场景自动切震动 |
| 姿势库审美主观 | 推荐姿势不好看 | 内测打分，淘汰低分姿势；先窄后宽 |
| 素材版权 | 上架风险 | 全部自有拍摄或购买授权，保留授权文件 |
| 用户没耐心 | 中途放弃 | 3 秒内给出第一条可执行指令；先易后难 |
| 上架审核 | 延误发布 | 隐私政策、权限说明、软著提前准备 |
